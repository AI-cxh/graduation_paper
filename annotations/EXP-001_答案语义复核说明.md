# EXP-001 答案语义复核说明

## 目的

`annotations/exp001_smoke_semantic_review.csv` 包含首轮 150 条输出。`manual_review_required=true` 的 110 条是规则无法高置信处理的优先队列；其余样本保留用于规则命中抽检。自动规则只用于筛选和诊断，人工复核结果才用于估计规则误差并形成语义正确率。

官方 MMMC 代码使用 ROUGE、GPT-4o 语义评分和独立幻觉判断。本项目首先保留可离线复现的词级指标和规则证据；未来如加入 LLM judge，不能把它作为唯一判据，且必须报告模型、prompt、重复一致性和人工抽检结果。

## 不同条件的复核目标

### `multimodal_conflict`

- `human_semantic_correct=yes`：回答明确指出问题前提不受图像支持，或正确纠正了错误对象、属性或关系。
- `human_semantic_correct=no`：回答接受错误前提、给出猜测答案，或只描述无关图像内容而没有解决问题。
- `human_semantic_correct=uncertain`：图像、问题或参考答案本身含糊，无法稳定判断。
- `human_stance` 填 `reject_premise`、`abstain`、`answer_premise` 或 `other`。

### `text_only_conflict`

该条件没有图像证据，不把它的输出解释为视觉任务正确率：

- `human_semantic_correct` 填 `n/a`；
- `human_stance` 只记录 `reject_premise`、`abstain`、`answer_premise` 或 `other`；
- 重点观察语言先验是否单独触发拒绝或猜测。

### `multimodal_clean`

- `human_semantic_correct=yes`：生成答案与参考答案语义一致；允许自然的扩写。
- `human_semantic_correct=no`：答案与参考答案矛盾，或没有回答问题。
- `human_semantic_correct=uncertain`：参考答案过短、图像存在多个合理答案，或生成回答只部分正确。
- `human_stance` 填 `n/a`。

## 填写规则

1. 不修改 `image_id`、条件、问题、参考答案、生成答案和自动指标列。
2. 只填写 `human_semantic_correct`、`human_stance` 和 `human_notes`。
3. 不因生成答案更详细就默认正确；检查是否包含矛盾、多个互斥候选或不确定措辞。
4. 规则命中但未进入复核表的样本仍需随机抽检，首轮至少抽检每种自动规则 5 条；样本不足 5 条时全部检查。
5. 正式论文结果应报告人工复核覆盖率、规则精度估计和未决样本比例。

## 填写后的校验

在仓库根目录运行：

```bash
.conda/bin/python scripts/summarize_exp001_semantic_review.py \
  --require-complete
```

程序会检查重复键、非法标签及不同条件下的 `n/a` 约束，并将汇总写入
`outputs/metrics/exp001/qwen2_5_vl_3b_human_review_summary.json`。若仍有必填字段
为空，命令会明确报出完成数量，不会把缺失标签计作错误答案或零分。

## AI 预复核的使用边界

`annotations/exp001_smoke_ai_prereview.csv` 是逐图生成的 AI 辅助预标注，不是独立
人工标签，不能直接报告为 human evaluation。其字段含义如下：

- `ai_semantic_correct`、`ai_stance`：AI 建议标签；
- `ai_confidence`：`high`、`medium` 或 `low`；
- `ai_notes`：判断理由或数据质量疑点；
- `human_confirmation`：真实复核者填写 `accept` 或 `edit`；
- `human_correction_*`：选择 `edit` 时填写修正标签。

建议先复核所有 `low` 和 `medium` 样本，再随机抽查 `high` 样本。只有真实复核者
确认后的标签才能转入 `human_*` 字段并用于论文语义正确率。
